# Handover — 2026-08-10 (updated)

## Goal
"LuxLibrary OS" — a premium personal-library operating system for a 2,000+ book collector (Dhanu), built from an extensive 11-phase spec (dashboard, catalog, AI librarian, collections, analytics, reading tracker, etc.). Built iteratively via bare "next" prompts, one module or batch at a time: marketing page → app shell → every IA screen against mock data → a real Neon Postgres database → migrating every page off mock data → full CRUD (add/edit/delete) with an ever-more-complete catalog-field set → CSV import → real reading-session tracking → the last unbuilt nav screen → wiring up every remaining unused schema field.

Add/Edit share a 4-up "W / H / D / Wt" number-input row plus a plain text QR-code field (manual entry — no barcode-rendering library, per the prior session's deliberate scope cut). Still merges only by exact `isbn13` match (see Next steps #3).
- **Reading progress and dates are really tracked.** Moving a book to "reading" opens a `ReadingSession`; moving away closes it; moving to "completed" sets `readingProgressPercent` to 100. `lib/reading.ts` prefers this real data and falls back to a `hashCode()`-derived placeholder only for books that have never gone through a real transition (the original 4 seeded "reading" / 13 seeded "completed" books — verified this never changes their displayed numbers).

- **Shelf assignment is now real.** Add/Edit both have a Shelf select + a Position number field, gated by shelf selection. CSV import gained matching `shelf` (label, case-insensitive lookup, no upsert) and `shelfPosition` columns. ## Key decisions
- **The hash-derived-placeholder bug class**: `lib/book-detail.ts`'s `getBookDetail(book)` derives fields from a hash of `book.id` — fine for the original mock `MOCK_BOOKS` (stable "1".."28" ids), silently wrong for a database book (a real cuid the hash was never seeded against). This bit Publishers, Quotes, Search, AI Librarian, and Analytics before being fixed one at a time; confirmed via grep it's now called nowhere outside `prisma/seed.ts`. **The generalized lesson, proven true twice**: don't trust a prior "fully migrated" claim — verify with a grep or directory diff before building on it. A fallback branch (like `lib/publishers.ts`'s old `?? getBookDetail(book).publisher`) is easy to miss when auditing by feature instead of by call site.
- **Grep-the-schema-before-picking-a-task is now the default way to find real work here.** Two rounds of this found: `/library-map` had zero page despite being in nav since day one; `Tag`/`BookTag`, `isFavorite`/`isRare`, `subtitle`, `isbn10`, `originalPublicationYear`, `country`, `isSigned`, `isFirstEdition`, `isLimitedEdition` all had zero references anywhere in the app despite being real schema-level columns. `weightGrams`/`widthMm`/`heightMm`/`depthMm`/`qrCode` are the remaining known-unwired fields (lower value per field, deliberately left).
- **Edit's initial values must come from the raw field, not a display-fallback field.** `getBookDetailFromDb` returns both raw values (`book.publisher`, `rawCondition`, `rawLanguage`) and display-formatted ones with fallbacks (`publisher` → `?? "Unknown"`, `condition` → humanized, `language` → `?? "English"`). `EditBookDialog` must be fed the raw ones — feeding the display value means editing an unset-publisher book literally saves a `Publisher` row named "Unknown". Check for this trap before wiring any new field into Edit.
- **Add gets cataloging-time fields; Edit-only gets fields that only make sense after ownership.** Condition/language/subtitle/isbn10/etc. are in both Add and Edit. personalReview/personalNotes/purchaseDate/purchaseSeller/currentMarketValue/insuranceValue are Edit-only — you don't have a review or purchase history for a book you're adding right now.
- **A `"use server"` file can only export async functions.** `lib/book-actions.ts`'s upsert helpers (`resolvePublisherId`, `resolveSeriesId`, `resolveTagIds`) are exported and async, so that's fine; the sync `isUniqueConstraintError()`/`duplicateKeyMessage()` checks live in a separate plain file (`lib/prisma-errors.ts`) so both `book-actions.ts` and `import-actions.ts` can import them.
- **On this Prisma 7.9.1 + `@prisma/adapter-neon` combo, a P2002 unique-constraint error's `error.meta` comes back `{}` — `meta.target` is NOT populated**, even though the offending column name is right there in `error.message` (e.g. `` Unique constraint failed on the fields: (`"qrCode"`) ``). Code written against `meta.target` (this project's own `qrCode`-vs-`isbn13` duplicate-message logic, added and shipped un-verified two sessions ago) silently always fell through to the wrong branch. `lib/prisma-errors.ts`'s `uniqueConstraintTarget()` now falls back to regexing the field name out of `message` when `meta.target` is empty. Caught only by actually triggering a real duplicate-key error end-to-end in the browser and reading server logs (`preview_logs`) — a case where "it typechecks and the happy path works" was not enough; error-path behavior needs its own live test, not just a build.
- **Author/genre/tag relations are re-linked via delete-then-recreate, not update-in-place**, in both `updateBook` and CSV import's update branch — they're composite-PK join rows keyed on the old id, not a reassignable field. Renaming an author this way does not clean up an orphaned `Author`/`Genre`/`Tag` row (0 books) — deliberately left, since every listing page derives its list from books' relations, not the lookup tables directly, so an orphaned row is invisible everywhere and costs nothing to leave.
- **A new mutation path must replicate reading-session tracking, not just the field write** — it isn't enforced by the schema or a shared helper, just convention. CSV import initially bypassed it (direct `prisma.book.create`/`update`, skipping the open/close-session logic `addBook`/`updateBook` have) until caught by testing the "set status to Reading via CSV" path directly. Any future 4th way to write `readingStatus` needs the same logic copied in.
- **`isbn13` is `@unique` on `Book`** — `addBook`/`updateBook`/CSV import all catch the Prisma `P2002` code and return/report a friendly "already in your library" message. A blank ISBN is sent as `undefined`/`null`, never `""` (an empty string would collide across every ISBN-less book under the unique constraint).
- **CSV import processes rows sequentially, not via `Promise.all`**, so one bad/duplicate row is skipped with a specific reason instead of racing concurrent upserts or aborting the whole batch. `lib/csv.ts` is a plain pure-function parser with no server directive, reusable client or server side.
- **Delete is a two-click same-button confirm** ("Delete" → "Confirm delete?" → deletes), not `window.confirm()` (blocks the event loop, looks out of place) and not a separate dialog component.
- **Dashboard's "curated" content (today's pick, AI insights, favorite genres/authors) is computed live from real data**, same rule-based-but-honestly-labeled philosophy as AI Librarian — see `lib/dashboard.ts`. Reading streak (`MOCK_STATS.readingStreakDays`) is the one deliberately-still-mock stat; there's no real streak-tracking data source.
- **Profile has no real per-user data model** (single-owner app, no `User` table) — rather than fabricate editable-but-non-persisting name/bio fields (misleading in a way Settings' toggles aren't), it's entirely real DB-derived aggregate stats plus the static owner-name/streak constants the rest of the app already treats as given.
- **Every DB-backed page needs `export const dynamic = "force-dynamic"`**, or Next bakes it into a static snapshot at build time using whatever was in the DB during `next build`, then never refreshes. Not caught by `tsc` — only visible in `npm run build`'s route table (`○` static vs `ƒ` dynamic).
- **shadcn/ui here is built on Base UI, not Radix.** Components take a `render` prop instead of `asChild`, and a non-`<button>` render target needs `nativeButton={false}` or Base UI logs a console error.
- **Prisma 7 moved connection config out of `schema.prisma`** into `prisma.config.ts`; `PrismaClient` requires an explicit driver `adapter` (`@prisma/adapter-neon` here). `prisma.config.ts` reads `process.env.DATABASE_URL` directly, not the throwing `env()` helper, so `prisma generate` survives a build before any database exists.
- **A live DB call in `app/(os)/layout.tsx` would force every page under it into dynamic rendering**, even ones with no DB dependency of their own (`/ai`, `/settings`, `/library/import` were static). When a global/topbar-level client component needs server data that only a few pages' worth of DB calls justify fetching on every navigation, prefer a small `"use server"` action the client component calls lazily (e.g. on dialog open) over threading the fetch through the shared layout.

## Gotchas / constraints learned
- **The Neon serverless driver (`@neondatabase/serverless` + `ws`) throws a transient `ETIMEDOUT`/connection error under `next dev`** — a page 500 with digest `2829966751@E394`, browser-console `Uncaught Error: {clientVersion: "7.9.1"}`. Reliably tied to a route's *first* request after a dev-server restart or a brand-new route's first Turbopack compile, not random. Always a false alarm (confirmed repeatedly by re-running the same DB calls in a standalone `tsx` script, and by reloading — resolves within 1-3 reloads). Don't debug application code in response to this; only suspect real logic if a fresh route still fails after 3+ reloads with the dev server otherwise idle.
- **The Browser-pane preview tool's accessibility-tree label for an `<input>` falls back to `placeholder` even when the input has a real, non-empty `value`** — a correctly pre-filled Edit field looked empty in `read_page` output. Verify actual DOM state with `javascript_tool`'s `document.querySelector(...).value` before concluding a pre-filled field is broken.
- **The Browser-pane tool can fail to visually show server-streamed Suspense content even when the server response is correct** (same underlying RAF-never-fires limitation as above) — confirmed via `fetch()`ing the page directly and finding correct HTML sitting in a hidden `<div id="S:*">` that never got swapped into view. `components/home/animated-counter.tsx`'s RAF-driven count-up animation is similarly always frozen at its initial value in this tool despite correct underlying data (confirmed via `curl`).
- **This machine's `gh` CLI has two cached GitHub accounts** (`dhanu-af`, `khdanushka-spec`). Before any push here: `gh auth status`, then `gh auth switch --hostname github.com --user khdanushka-spec`, push, then switch back to `dhanu-af` afterward so Dhanu's other projects on this machine aren't disrupted.
- Windows: stop the local dev server before running `prisma generate`/`migrate` (file lock on the query engine `.dll.node`).
- `npx vercel integration add neon --claim --environment production --environment preview --environment development` provisions a real Neon DB via the Vercel Marketplace and writes credentials to `.env.local` (gitignored) in one command.
- `dotenv` prints a rotating promotional "tip" line on every `config()` call — cosmetic, not a security concern.

## Next steps
1. Cover images need real file storage (Vercel Blob or similar) — a genuine infra/cost decision, not done unprompted across multiple sessions. Ask before provisioning.
2. `ReadingSession` only auto-tracks `startedAt`/`endedAt` on status transitions — `minutesRead`/`pagesRead` per-session aren't captured, and a book cycling reading → unread → reading gets two separate session rows with no UI to see the first one.
3. CSV import's field set now matches Add Book, but the *merge* logic is still exact-`isbn13`-only (two rows for the same book with different/blank ISBNs both import separately). Could extend to also match on `qrCode`.
4. Notes/Quotes have Add + Delete but no Edit yet — a typo in a saved note or quote currently means delete-and-re-add.
5. Shelves can now be created and deleted (see State), but there's no *rename* — changing a shelf's room/capacity/label after creation means delete-and-recreate (only possible when it's empty, since delete is blocked while books reference it).
6. **This is a strong check-in point with Dhanu, more so than prior sessions' version of this note.** Every nav screen exists, every simple `Book` column is wired into Add/Edit/Book-Detail/CSV-import, shelf management (create/assign/delete) is real, and Notes/Quotes are real CRUD instead of read-only seed data.
